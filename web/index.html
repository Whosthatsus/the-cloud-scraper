Serverless Step Functions ETL Workflow Pattern

AWS Step Functions State Machine

The Cloud Scraper replaces traditional manual file uploads with an active, automated pipeline orchestrated by AWS Step Functions. Below is the full state machine transition pattern:

1 Trigger EventBridge / API Gateway
→
2 Dispatcher Lambda + SQS Job Queue
→
3 Orchestrator AWS Step Functions
→
4 Scraper Requests + BS4 (robots.txt)
→
5 Validator Schema & Quality Filter
→
6 Transform SHA-256 Deduplication
→
7 Storage Local JSON & DynamoDB
→
8 Telemetry FinOps Cost & SNS Alert
🛡️

Fault Tolerance & Dead-Letter Queue (DLQ) Architecture

Any state failure in the Step Functions state machine is caught by a fail-safe catch block. The failed execution payload is quarantined into the Amazon SQS Dead Letter Queue (ScraperDLQ) to prevent pipeline stalling and preserve error lineage for redrive replay.
